# Design principles

- Keep a skill project- and technology-agnostic unless its behavior inherently depends on a technology.
- Give each skill one responsibility and a discriminating trigger condition.
- Keep the entrypoint concise; preserve non-obvious boundaries and route conditional detail only when it changes decisions.
- Respect existing approval boundaries. A skill never creates permission for external, destructive, or product-changing actions.
- Prefer observable evaluation of behavior over wording checks alone.
